# 金融知识库问答系统（LangChain RAG 练手项目）

> **一句话说清它是什么**：往网站里上传你的资料（研报、基金说明书、政策文件……），然后像聊天一样问它问题。它**只根据你上传的资料**回答，还会告诉你答案是从哪段资料里来的、可以点开核对原文。

这是一个用来练手 + 毕业设计/简历储备的**企业级 RAG 知识库问答系统**。技术栈比较完整（网页前端 + 后端接口 + 向量检索 + 大模型），但每一步都按"新手能看懂"的思路组织。

看不懂术语没关系——本文每一处专业名词旁边都配了大白话解释。整体建议顺序：先看第 2 节功能 → 照着第 5 节跑起来 → 第 6 节点一点 → 其余按需看。

---

## 1. 这个项目解决什么问题

常见的信息获取方式有两个痛点：

- **问通用大模型**（如直接问通义千问）：它可能"胡编"，也不一定懂你私有的资料（比如一份没公开的研报）。
- **自己翻资料**：几十份 PDF 里找一个数据，累。

这个系统把两者结合起来：**先把你的资料"喂"给它，再问它**。于是它能：

1. 回答基于你自己的资料（不胡编，资料里没有的它会说"没提到"）；
2. 每条回答附上**来源片段**，点开能看原文，方便核对真假；
3. 一个网站多个人用，每个人的**问答历史互相看不见**，关掉浏览器再打开，历史还在。

## 2. 主要功能一览

| 功能 | 说明 | 谁可以用 |
|------|------|----------|
| 注册 / 登录 / 修改密码 | 账号密码存在数据库里，密码是加密保存的 | 所有人 |
| 问答 + 引用来源 | 提问后给出回答，并列出回答依据的资料片段 | 登录用户 |
| 多会话 | 左侧可以建多个会话，像微信里多个对话框，互不串味 | 登录用户 |
| 会话历史持久化 | 关掉浏览器、过几天再来，历史还在；每个会话的问答按时间排好 | 登录用户 |
| 知识库管理 | 上传资料（txt / md / pdf）、查看已入库的清单、删除资料 | **仅管理员** |
| 隐私隔离 | 普通用户之间、普通用户和管理员之间，会话和知识库都隔开 | 系统自动保证 |

> 内置示例：第一次启动会自动往知识库里放一份示例研报（华辰智造），这样不用上传任何东西就能先试提问。

## 3. 用到的技术（每个都解释是干嘛的）

下面这排名字就是大家常说的"技术栈"。列出来是为了让懂行的人一眼看懂，**看不懂没关系，右边有解释**：

| 技术 | 在这个项目里扮演什么角色 | 大白话 |
|------|--------------------------|--------|
| Python + FastAPI | 后端（写接口的那一半程序） | 网站的"后台服务员"：收请求、查资料、给回答 |
| Vue 3 + Element Plus | 前端（浏览器里看到的那一半） | 画出登录页、聊天窗口、上传按钮这些界面 |
| 通义千问（阿里云 DashScope） | 大模型，负责"组织语言回答" | 一个很聪明的"写手"，但它只看你喂给它的片段 |
| text-embedding-v3（阿里云） | 把文字变成"向量"的模型 | 把一段话翻译成一串数字，意思越接近的数字越像 |
| Milvus（向量数据库） | 存"向量"并快速找最像的 | 一个专门"按意思找相似内容"的仓库 |
| LangChain | 把上面这些串起来的小工具包 | 胶水：帮你少写很多样板代码 |
| MySQL（可临时切 SQLite） | 业务数据库（账号、会话、文档清单） | 记账本，记谁登录了、聊了什么 |
| JWT + bcrypt | 登录令牌 + 密码加密 | 登录后发一张"临时通行证"；密码不以明文存 |

**为什么是这套组合**：大模型负责"会说话"，向量检索负责"只谈你的资料"——两者分工，回答既有质量又不离题。这套结构是目前行业里做"私有知识库问答"的主流做法，答辩、求职都能讲。

## 5. 在自己电脑上跑起来（首次约 10 分钟）

### 先准备这几样东西

1. **Python 3.10 或更高**（装依赖、跑后端用）
2. **Node.js 20 或更高**（装前端用）
3. **Docker**（业务数据库 MySQL 用 Docker 跑，见第二步）
4. **一个阿里云 DashScope（百炼）API Key** —— 就是给通义千问付费的钥匙，开通后控制台里能找到。这是**唯一要花钱的地方**，问答量小的话一年几块钱级别。

> 注意：跑起来后提问需要**能联网访问阿里云**，断网会报错。

### 第一步：填密钥

在 `LangChainRAG/` 文件夹下新建一个文件，名字叫 `.env`（没有后缀），内容填两行：

```
DASHSCOPE_API_KEY=你的阿里云API密钥粘贴到这里
SECRET_KEY=随便写一长串字母数字（给登录令牌签名用，别外传）
```

> `.env` 已经被 git 忽略，**永远不会被提交到代码仓库**——密钥只在你本机。这一点很重要，别把 key 贴到别处。
>
> 数据库连接不用写在 `.env` 里：开发默认值和 `docker-compose.yml` 已对上，直接跑即可。想临时换回 SQLite 时，再在 `.env` 加一行 `DB_URL=sqlite:///你的绝对路径/langchain_rag.db`。

### 第二步：先起 MySQL，再启动后端

先启动数据库（在 `LangChainRAG/` 目录）：

```powershell
docker compose up -d    # 第一次会自动拉 mysql:8.0 镜像，需联网，约一两分钟
```

后端（在 `LangChainRAG/` 目录再开一个终端）：

```powershell
python -m venv .venv          # 第一次：建一个独立的 Python 环境
.venv\Scripts\activate        # 进入这个环境（激活后命令前会多出 (.venv)）
pip install -r requirements.txt   # 第一次：安装所有依赖
uvicorn app.main:app --reload --port 8000   # 启动后端
```

> 以后每次开电脑：先 `docker compose up -d` 把 MySQL 起好，再启动后端就行。

看到 `Application startup complete` 就是成功了。此时：

- 接口服务：http://127.0.0.1:8000
- **自动生成的接口文档**：http://127.0.0.1:8000/docs （浏览器打开，能直接点按钮调试每个接口）

### 第三步：启动前端（另一个终端）

```powershell
cd frontend
npm install          # 第一次：安装网页依赖
npm run dev          # 启动网页
```

看到提示后，浏览器打开 **http://localhost:5173**（注意是 localhost，不是 127.0.0.1，Windows 上这俩不一样）。

### 第四步：登录使用

用内置管理员 **wly / 123456** 登录，左侧会多出"知识库管理"菜单。也可以点"注册"新建普通账号。

## 6. 怎么用（图文步骤）

### ① 提问

1. 左侧输入框打字，回车或点发送。
2. 第一次提问会自动新建一个会话（左侧会话列表会多一条，标题就是你的问题）。
3. 回答下方会有几段"引用来源"（默认取 3 段），点开能看原文片段，确认它没瞎编。

### ② 管理多个会话

- 左侧是会话列表，点一条切换；不同会话之间互不影响。
- 每个会话标题默认取你第一个问题，简短好认。
- 右上角或会话上可以删除会话（只删你自己的，删别人的会被系统挡住）。

### ③ 上传资料（管理员）

1. 点左侧"知识库管理"。
2. 拖一个文件进来（支持 `.txt` `.md` `.pdf`，**单文件 ≤ 10MB**），填个标题，点上传。
3. 上传后会自动：切块 → 转向量 → 入库。列表里能看到它切成了几块。
4. 立刻就能去问答页问它——不需要任何额外操作。

### ④ 删除资料（管理员）

在知识库列表点删除，确认后：向量库里的相关片段、上传原件、数据库记录一起清掉。删完后，再问相关问题时它只会老实回答"资料中未提及"，不会引用已删除的内容。

### ⑤ 改密码 / 看自己账号

左下角头像区 → 个人中心：查看登录名、角色，改密码。

## 8. 接口一览（想自己调 API 的人看）

前端调的就是下面这些，浏览器打开 `http://127.0.0.1:8000/docs` 可以直接点点点调试。

| 接口 | 作用 | 要不要登录 |
|------|------|-----------|
| `POST /api/auth/register` | 注册 | 不用 |
| `POST /api/auth/login` | 登录，拿令牌 | 不用 |
| `GET /api/auth/me` | 查当前登录的人 | 要 |
| `POST /api/auth/change-password` | 改密码 | 要 |
| `GET /api/conversations` | 我的会话列表 | 要 |
| `POST /api/conversations` | 新建空会话 | 要 |
| `GET /api/conversations/{id}/messages` | 某会话的历史消息 | 要（只能看自己的） |
| `DELETE /api/conversations/{id}` | 删会话 | 要（只能删自己的） |
| `POST /api/ask` | 提问（回答 + 引用 + 返回会话 id） | 要 |
| `GET /api/documents` | 知识库清单 | 要 + 管理员 |
| `POST /api/documents/upload` | 上传资料 | 要 + 管理员 |
| `DELETE /api/documents/{id}` | 删除资料 | 要 + 管理员 |

登录方式：调 `/api/auth/login` 拿到 `token`，之后每个请求带一个请求头 `Authorization: Bearer <token>`。

## 10. 这个项目的亮点（讲给别人听 / 答辩能用）

- **引用来源**：回答带资料片段出处，能溯源、防胡编——这是 RAG 的核心价值，也是面试常考点。
- **多用户 + 权限隔离**：会话按人隔离（拿不到、删不掉别人的），知识库只对管理员开放。
- **异常兜底扎实**：上传失败会自动回滚数据库并清理残留文件；删除时向量库删失败不阻塞；越权/未登录都返回明确错误。
- **配置化 + 可迁移**：密钥、模型名、数据库地址都集中在 `config.py`，换数据库只改一行。
- **注释写"为什么"**：每个函数都有大白话 docstring，代码本身就能当教程读。

## 11. 上线 / 部署前必须处理的安全清单

这套代码用于练手是安全的（真实密钥已确认不会进 git）。但真要部署给别人用时，以下几条**必须**改：

1. **管理员密码写死在代码里**（`config.py` 的 `wly / 123456`）→ 改成从 `.env` 读。
2. **SECRET_KEY 有兜底默认值** → 改成"没读到就拒绝启动"，防止悄悄用弱默认值。
3. **CORS 全放开**（`main.py` 里 `allow_origins=["*"]`）→ 上线时收紧成你自己的域名。
4. **注册完全开放** → 如不想让陌生人注册，加注册开关或邀请码。
5. **requirements.txt 没锁版本号** → 部署前固定具体版本，保证别人装出来环境一致。
6. **MySQL 开发密码写死在 compose 里**（`rag_dev_pass`）→ 部署时通过 `.env` 的 `DB_*` 覆盖成强密码。

## 12. 还能怎么优化（按优先级排，给想继续做的人）

### 功能 / 数据库层面（最推荐先做）

1. **换 MySQL 数据库** ✅（第 8 步已完成）：业务库已换成 MySQL，`docker-compose.yml` 一键起。后续可选：把 MySQL 和真 Milvus 一起容器化、统一编排。
2. **起真正的 Milvus（Docker）**：现在向量库用的是 Milvus 的"单文件演示版"（Milvus Lite）。部署时在 Docker 里起正式版，也只需改 `config.py` 一行地址。好处：能支撑更大数据量、更多并发。

### 回答体验层面（答辩加分项）

3. **流式输出** ✅（第 8 步已完成）：新增 `/api/ask/stream`（SSE），网页现在是打字机效果，边生成边显示。
4. **检索更聪明（混合检索 + 重排）** ✅（第 8 步做了一半）：候选从 3 段扩到 15 段，再做"BM25 关键词 + 语义排名"融合精排（`app/reranker.py`）。将来可选：换真正的神经网络重排模型（如 bge-reranker），更准但要下载模型。
5. **智能切块**：现在是按固定长度切段。改成按标题结构切，一段就是一个完整小节，引用更"干净"。

### 性能 / 工程层面

6. **热点问答缓存（Redis）**：高频问题先查缓存，命中就秒回，省大模型调用费。
7. **上传大文件后台处理（Celery）**：现在上传要等它切块转向量完才返回；改成后台异步做，前端先回"排队中"，不卡界面。
8. **接口限流**：给接口加每分钟次数限制，防止有人刷爆你的 API 账单。
9. **支持更多文件格式**：docx、xlsx、网页链接等（现在支持 txt / md / pdf）。

### 前端打磨

10. 会话加载态、上传进度条、流式打字效果、移动端适配。

## 13. 踩过的坑（后来人省时间）

- **Milvus Lite 装不上**：`pip install pymilvus` 后本地引擎可能没跟着装上，报 `No module named 'milvus_lite'`。解决办法：再手动 `pip install milvus-lite`（在某些 Python 新版本上尤其需要）。
- **删了向量库文件别慌**：如果把 `milvus_lite.db` 删了，下次启动后端会自动**从 `data/uploads/` 里的原件重建**向量库，不会全丢。
- **两个端口别搞混**：后端在 8000，前端在 5173；前端页面打不开时先确认是不是敲成 127.0.0.1:5173（要 localhost）。
- **提问报错先查网络**：断网、或阿里云 key 填错，是问答报错最常见的原因，先查这两样。

## 附：它的原理，一句话版（RAG 是什么）

这个系统的英文缩写叫 RAG（检索增强生成），原理拆成两步讲：

1. **你上传资料时**：系统把整篇资料切成一小段一小段（每段几百字），每段用"文字转数字"模型变成一串数字（这串数字叫**向量**，能概括这段话的意思），连原文一起存进向量库。
2. **你提问时**：系统把你的问题也变成一串数字，去向量库里找出**意思最接近的 3 段**，然后只把这 3 段原文 + 你的问题一起发给大模型，并叮嘱它："只准照着这几段回答，别自己编。"

于是：**答案有出处、可核对、不胡编**——资料里没有的内容，它会老实说"资料中未提及"。
